The Rust server

agentkit::server (feature server) is built on axum. serve binds a listener of its own and returns its URL and a close handle:

To mount the routes in an axum app of your own, create_agent_handler(&agent, opts) returns an AgentHandler. Its router() is an axum::Router: with base_path set it answers under that prefix, and any path it does not own falls through to your app's routes and fallback (TypeScript's next()).

The handler is not a bare Router because a Router cannot be closed: handler.close().await ends its event streams, so a graceful shutdown does not wait on open SSE connections forever. create_agents_handler does the same for several agents.

The routes are the TypeScript list: POST /session, GET /events (SSE with keep-alive comments), GET /events/all, POST /send, /approve, /reject, /answer, /cancel, GET /approvals, /history, /artifacts, GET|POST /mode, /todo/edit, /workflows*, /mcp* (with the OAuth callback), /rag/*, /models*, /health, /capabilities. With transport: Some(Transport::WebSocket), /events is a WebSocket. Auth, tenant isolation (tenant_header), CORS, Host checks (allowed_hosts, default on a loopback bind), the 4 MiB body limit and the session cap (max_sessions) are ported from handler.ts.

Each event stream has its own queue, written by the response body (or the WebSocket task), so a slow client never stalls the agent. A stream joins its session before its headers go out (for WebSocket, before the handshake completes), and a session route waits, briefly, for its streams to write what its call raised before it replies: /send cannot answer ahead of its tokens. Where the routes differ from TypeScript's, it is because of axum: a WebSocket upgrade with no sessionId or failed auth answers 400 or 401 instead of dropping the socket.

The Rust client

agentkit::client (feature client) talks to any AgentKit server:

It reconnects dropped streams with backoff, connect_with_retry waits for a server that is still starting, and connect_agents(url, opts) talks to serve_agents. The session hub folds events with the same reducers as the TypeScript client (conversation, pending, plan, todos, usage, workflow), in client::state. The client depends only on the wire vocabulary (agentkit::wire and agentkit::types), never on the runtime, as @agentkit/client imports only core's wire types.

Three things differ from TypeScript. Handlers for server events run on the task that reads the stream, so keep them short or hand work off. close() returns at once (a handler may call it) while shutdown().await also waits for that task. And dropping a Session closes its event stream, as dropping the last clone of a SessionHub closes the hub, so hold on to them while you listen. send waits for a stream that is still connecting, then returns once the handlers have seen the run's done.

How the sameness is checked

The client contract, in all sixteen pairings. A contract host in each language (sdks/conformance/contract/ts_host.mjs, python_host.py, the Go one in sdks/go/internal/contracthost, and sdks/rust/examples/contract_host.rs) builds an agent from a JSON config and serves it on a free port (POST /serve, /serve-agents, /close). TypeScript's packages/server/src/client-contract.test.ts runs unmodified against any host, and so do its Python, Go and Rust ports (the Rust one is sdks/rust/tests/contract):

The wire frames, byte for byte. sdks/conformance/fixtures/wire.json holds the AG-UI frames the TypeScript adapter produces for every event name; the Rust server replays them exactly. CI regenerates every fixture from the TypeScript source and fails on any difference.
