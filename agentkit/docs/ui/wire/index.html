The wire protocol

Every AgentKit server speaks one wire: JSON over HTTP for actions, and a stream of events over Server-Sent Events (or a WebSocket) for everything the agent does. The envelope follows AG-UI, so third-party AG-UI consumers can read it too. The TypeScript, Python, Go and Rust servers have the same routes, status codes, JSON bodies and event frames, and the same is true of the four clients. Any client works against any server:

ClientTypeScript serverPython serverGo serverRust server
@agentkit/client (TypeScript, browser or Node)yesyesyesyes
@agentkit/react, @agentkit/vue, @agentkit/svelteyesyesyesyes
agentkit.client (Python)yesyesyesyes
client package (Go)yesyesyesyes
agentkit::client (Rust, feature client)yesyesyesyes

In practice: write the UI once with the TypeScript packages, and choose the backend language for other reasons (your team, your data stack, your deployment). Moving the backend from TypeScript to Go, or from Python to Rust, changes no UI code. You do not need this page to use AgentKit, since the clients wrap all of it; it is the reference for writing your own client or debugging one.

A session, step by step

Section titled “A session, step by step”

  1. Create a session. POST /session with {} answers { "sessionId": "..." }. Send { "sessionId": "existing" } to resume one.

  2. Open the event stream. GET /events?sessionId=<id> is an SSE stream. Each message is one JSON envelope, { "type", "payload", "timestamp" }. The server sends a : ping comment every 15 seconds so proxies keep the connection open.

  3. Send a message. POST /send with { "sessionId": "<id>", "input": "your message" }. While the run goes, events arrive on the stream (stream:token, tool:call, approval:request, …). The POST answers when the run ends, with { "result": { "output", "status", ... } }.

  4. Answer the agent. When the stream carries approval:request or elicitation:request, post /approve, /reject or /answer with its requestId. POST /cancel stops the run in flight.

Frames

Section titled “Frames”

Every event is one envelope:

  • SSE: each envelope is one data: line followed by a blank line. No event: or id: fields are used; read the type from the JSON.
  • WebSocket (transport: "websocket" on the server): GET /events?sessionId=<id> upgrades, and each text message is one envelope. The REST routes stay HTTP.
  • GET /events/all: one stream for every session of the tenant. Each envelope also carries "sessionId", so one connection can keep many chats live.

sdks/conformance/fixtures/wire.json holds the exact frame the TypeScript adapter produces for every event name. The Python, Go and Rust servers replay that fixture byte for byte in their tests.

Events from a workflow step or a subagent carry a scope, so a UI can show them nested or leave them out of the main chat.

The clients also emit two local events that never cross the wire: client:send when your code sends a message and client:answer when it answers a question, so the user’s turn appears at once.

Headers

Section titled “Headers”
  • Authorization: Bearer <token>: checked by the server’s auth hook, if it has one.
  • x-agentkit-tenant: <tenant> (the name is configurable): namespaces sessions per tenant.
  • Content-Type: application/json: required on POST, PUT and PATCH, else 415.

Status codes

Section titled “Status codes”
CodeMeaningWhat a client does
200Done (a stopped run is a 200 too, with status: "stopped")
400Bad body (missing sessionId, unknown mode)Show the message
401, 403auth said no, or a refused Origin or HostStop; reconnecting will not help
404Unknown route, a feature the agent lacks, or an evicted sessionCreate a new session for 404 on /events
413Body over 4 MiBSend less
415Not JSONSet Content-Type
500The run failed; the body is { error }Show the message; a partial stream does not mean success

Errors are always JSON { "error": "..." }. Every client raises them as AgentKitError with status, message and the body; status 0 means the server could not be reached.

Consuming the wire without a client

Section titled “Consuming the wire without a client”

In a browser with no bundler, EventSource and fetch are enough:

Subscribe before you send

The server sends each event to the streams it knows at that moment and replays nothing. Open the stream and wait for it to be open before posting /send, or the first tokens are lost. The four clients do this for you: their send waits for the stream.

EventSource cannot send an Authorization header. With an auth hook, use @agentkit/client (it streams with fetch and sends the header) or put the agent behind same-origin cookies.

Where the servers differ

Section titled “Where the servers differ”

Only in host-language details that a client cannot see:

  • Python: the server is one framework-free ASGI app; serve runs it on uvicorn. WebSocket goes through the ASGI websocket scope.
  • Go: plain net/http; each stream has its own goroutine and queue.
  • Rust: axum; a WebSocket upgrade with no sessionId or failed auth answers 400 or 401 instead of dropping the socket.
  • TypeScript: Node http, Express middleware or a Fetch API handler.

Mounting and options for each are on Serve over HTTP; the clients are on Client.
