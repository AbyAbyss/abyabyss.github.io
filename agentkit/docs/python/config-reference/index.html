Config in Python

How createAgent's config, options and results map to the Python port

Config in Python

The Python port takes the same configuration as TypeScript. What changes is the host language around it: names, schemas, callables and async. This page lists each mapping and why it is that way.

The config dict keeps TypeScript's keys

create_agent(config) takes a dict with the keys from the config reference, spelled as in TypeScript:

  • The same keys, so configs move between engines. A config stored as JSON, sent over the wire or copied from the TypeScript docs works as is. The contract suite builds every agent from such JSON in both languages.
  • snake_case keys also work ("tool_search", "durable_sessions"). TypeScript would reject them; Python accepts both spellings.
  • Validation happens at construction, as with Zod. A bad config raises ValueError starting Invalid createAgent config:, listing each problem on its TypeScript path (context.compactAt: Input should be less than or equal to 1). Unknown keys are refused, so a typo fails loudly.
  • Presets (create_ui_preset, create_cli_preset, create_backend_preset) return such a dict; pass overrides as a dict: create_backend_preset({"mode": "plan"}).

Python names are snake_case

Functions, methods and keyword arguments follow Python conventions:

TypeScriptPython
createAgent(config)create_agent(config)
agent.run(task, { output, onApproval })await agent.run(task, output=Model, on_approval=fn)
agent.session({ userId, meta })agent.session(user_id="u1", meta={...})
agent.setMode("plan")agent.set_mode("plan")
agent.models.setDefault(id)await agent.models.set_default(id)
agent.mcp.completeAuth(id, code)await agent.mcp.complete_auth(id, code)
session.runWorkflow(id, input)await session.run_workflow(id, input)
createCodingAgentPreset({ root, provider })create_coding_agent_preset(root=..., provider=...)

Option and result objects are dataclasses with snake_case fields: RunResult (output, usage, trace, cost, step_count, tool_calls, trace_id, handoff), SQLConnectorConfig(dialect=, path=, max_rows=), ModelProviderConfig(id=, provider=, model=) for agent.models.add, HttpToolDef, ApiEndpointDef.

What is sent, stored or emitted keeps TypeScript's keys

Event payloads, wire bodies, recordings, session logs and anything persisted stay in TypeScript's shape, as dicts:

That is what lets a TypeScript UI read a Python server, and a log or recording written by one engine load in the other. Their types are TypedDicts in agentkit.types.events, so a type checker still sees the keys. agent.capabilities() returns the TypeScript keys too.

Functions are callables, and may be async

Every function-valued key takes a Python callable, sync or async:

KeyPython
systemdef system(ctx) -> str, where ctx is a PromptContext (user_id, org_id, meta, mode, task)
hooks.beforeModel, beforeTool, afterTool, onOutputreceive a context dataclass (ctx.messages, ctx.name, ctx.args, ctx.result, ctx.session.meta) and return a dict of changes ({"block": "why"}, {"args": ...}) or None
approvals.policylambda tool, session: "auto" | "approve" | "deny" | None
logging.destinationreceives {"level", "message", "data"}
telemetry.onSpansreceives a list of span dicts
onApproval, onElicitation (run or send options)async callables: on_approval=, on_elicitation=

Configured plugins are Plugin dataclasses (Plugin(id="audit", on_event=fn)); the field is id where TypeScript says name. Custom providers register with register_provider(id, factory), where the factory takes the optional API key from the config: def factory(api_key=None) -> Provider.

Everything that does I/O is async

run, send, close, the models / rag / mcp / workflows APIs, serve and every client verb are coroutines. Event handlers are plain callables. Cancellation is a CancelSignal (run(..., signal=)) where TypeScript takes an AbortSignal. Always await agent.close(), which disconnects MCP servers and closes memory and cache stores.

Where the port differs, and why

  • Code Mode programs are Python. python_code_runtime runs them in a separate python -I process with an empty environment, over the same JSON-lines tool RPC; the host refuses programs that import, name a dunder or touch frame attributes. TypeScript's node:vm runtime has no Python counterpart.
  • JavaScript semantics where they show. Compact JSON.stringify output, JavaScript number formatting (5.0 as 5, 1e+21), String(), encodeURIComponent and toFixed rounding are reproduced wherever their result reaches the wire, a prompt or a fixture, so output matches byte for byte.
  • SQL connectors are production pools. MySQL runs on an aiomysql pool and streams results; Postgres runs on a psycopg pool, sends parameters as untyped text as pg does, keeps prepared statements off so PgBouncer works, and counts rows past maxRows on the server with a cursor. rowCount stays the total, as in TypeScript.
  • SQLite stores close cleanly. Each SQLite-backed store closes its connection when closed, dropped or at exit, and works as a context manager.
  • The server is ASGI. agentkit.server is one framework-free ASGI app; serve runs it on uvicorn. See One wire, four engines.
  • The client is async only. agentkit.client replaced the stdlib scaffold that lived in clients/python.

Feature status

All of @agentkit/core, @agentkit/runtime, @agentkit/kernel, @agentkit/encoding, @agentkit/workspace, @agentkit/server and @agentkit/client (minus browser-only UI stores) are ported. The file-by-file checklist is Appendix A of docs/plans/python-go-sdk-port.md; sdks/python/README.md has the module table.
