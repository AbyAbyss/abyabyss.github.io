Streaming & wire protocol

Connect a frontend to @agentkit/server over AG-UI SSE

UI apps never import @agentkit/core in the browser. Run the agent with @agentkit/server (serve() or Express wrapper), then connect from the client with @agentkit/client, framework hooks, or raw fetch + EventSource (or WebSocket).

Architecture

Agent URLs in the examples: express-api serves page and agent on :8787 (agent at /api/agent), nextjs-chat mounts the agent in its own route (/api/agent on :3001), vanilla-js-ui serves both on :3001. Workflow UI uses :8788.

Serving an agent

@agentkit/server has four entry points with the same routes and hardening (body limit, random session ids, session cap, auth, tenant isolation, error mapping):

Options: auth, tenantHeader, cors ("*", an origin, true or { origins }), allowedHosts (accepted Host headers), keepAliveMs (SSE ping, default 15000), health (extra /health fields), maxSessions, mcpServers, artifactsDir, transport, and for serve/serveAgents also port, host and static (a directory, or { prefix: directory } to mount several, e.g. the client's browser bundle).

Session routes take sessionId in the JSON body (POST) or query (GET).

Workflow, MCP and RAG routes answer 404 when the agent doesn't have that feature.

Optional headers: Authorization: Bearer <token>, x-agentkit-tenant: <tenant> (multi-tenant sessions).

CORS is enabled for browser clients (Access-Control-Allow-Origin: * by default; restrict it with cors: { origins: [...] }). SSE streams send a : ping comment every 15 s so proxies keep them open.

Request checks, before routing:

  • Origin. With cors set to an origin or { origins }, a request whose Origin is neither allowed nor the server's own gets 403: every method, SSE streams and WebSocket upgrades. Requests without an Origin (curl, server-to-server) pass.
  • Host. allowedHosts: ["agent.example.com"] refuses other Host headers with 403 (an entry without a port allows any port), which stops DNS rebinding. serve() bound to a loopback address (the default 127.0.0.1) only answers to localhost, 127.0.0.1 and [::1] with its port unless you set allowedHosts; other binds have no check unless set.
  • JSON bodies. POST, PUT and PATCH need Content-Type: application/json, else 415 (no cross-site form posts). @agentkit/client always sends it.

Event stream (SSE, default)

  1. POST /session with {} (or { "sessionId": "existing" }).
  2. Open EventSource on GET /events?sessionId=<id>.
  3. Each message is JSON: { type, payload, timestamp }.
  4. POST /send with { sessionId, input: "your message" }.

Event stream (WebSocket, optional)

Pass transport: "websocket" to serve() or serveAgents(). Connect a WebSocket client to ws://host:port/events?sessionId=<id>. Messages use the same { type, payload, timestamp } JSON shape as SSE. REST routes (/send, /approve, …) are unchanged.

@agentkit/client uses SSE by default; use raw ws or extend your client for WebSocket transport.

In Node (no EventSource), the client falls back to fetch streaming the same SSE body.

Vanilla JS (no bundler)

See examples/express-api/public/index.html and examples/vanilla-js-ui/public/index.html. The server mounts the client's browser bundle next to the page (static: { "/": "./public", "/vendor": clientDist }, or express.static in Express), and the page imports it:

Run it: pnpm example:express:mock (or pnpm example:express live), then open http://127.0.0.1:8787.

Errors & reconnect

  • session.send throws when the server returns { error } (500) — show the message; do not assume partial stream means success.
  • SSE disconnect: EventSource auto-reconnects in browsers; re-bind handlers or use @agentkit/client which opens one stream per connect().
  • 404 on /events: session expired server-side; POST /session again.
  • Auth: pass token in connect() options; implement auth on serve() to validate Authorization.
