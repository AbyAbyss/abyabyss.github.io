Memory

Memory is what the agent remembers between turns. After each turn it appends the user message and the answer to a store, and before each model call it reads the recent entries back into the prompt. Entries are kept per namespace: an organisation, a user and a session, so one user’s history never leaks into another’s.

Memory is on by default, in the process’s own memory. Choose a persistent store when history must survive a restart or be shared by several servers.

You wantUse
The model to recall earlier turns of a conversationMemory (this page)
A session to resume exactly where it stopped after a restart, with its full transcript and stateDurable sessions (below)
The model to look things up in documentsRAG (Sources)
To skip repeated identical tool callsThe tool result cache (Tools)

Turn memory off with memory: false (Python "memory": False; Go &memory.MemoryConfig{Disabled: true}; Rust Some(MemoryConfig::disabled())). A stateless API endpoint that sends the whole conversation each time is the usual reason.

Postgres and Redis

Section titled “Postgres and Redis”

A shared store lets several server processes serve the same users. The Postgres store creates its table on first use (under an advisory lock, so two servers starting together do not race), and the Redis store keeps one list per namespace with the TTL applied as a key expiry.

  • TypeScript
  • Python
  • Go
  • Rust

Caution

Always close the agent when you are done (await agent.close(), defer a.Close(ctx), agent.close().await). It releases the store’s connection pool; a process that skips it can exhaust a database’s connection limit.

Scope memory to a user and a session

Section titled “Scope memory to a user and a session”

A session’s namespace comes from its sessionId, userId and orgId. Two sessions with the same ids share history (a user reopening a chat); different ids are isolated. Without ids, a session gets a generated sessionId.

  • TypeScript
  • Python
  • Go
  • Rust

agent.run() without a session uses a namespace of its own, so one-shot runs do not see each other’s history. The tenant config key sets a default userId and orgId for every session of an agent.

TTL and fact extraction

Section titled “TTL and fact extraction”

The helpers behind ttl and extract are public, which is handy for tests and for custom stores: parseMemoryTtl turns "7d" into a duration, and extractDurableFacts returns the facts a turn would add to long-term memory.

  • Python
  • Go
  • Rust

The built-in stores are public too: InMemoryStore, SqliteMemoryStore, PostgresMemoryStore and RedisMemoryStore in every language (in Go, the Postgres and Redis stores live in memory/postgres and memory/redis). Python, Go and Rust also export the factory behind the store key: create_memory_store, memory.CreateMemoryStore.

Durable sessions

Section titled “Durable sessions”

Memory recalls recent turns. A durable session goes further: the session’s whole state (transcript, mode, todos, pending work) is saved after every turn, so a session with the same sessionId resumes exactly where it was after a restart or on another server that shares the path.

  • TypeScript
  • Python
  • Go
  • Rust

Snapshots are JSON files, one per session, and the format is the same in all four languages: a Python server can resume a session a TypeScript server saved. saveDurableSession writes one by hand. The server also exposes saved sessions over HTTP, so a client can list and reopen them; see Serve over HTTP.

Events

Section titled “Events”

memory:updated fires after the store changes, with the namespace. Subscribe to it to refresh a “what the agent knows” panel or to mirror writes elsewhere.
