Case study: the grand tour

Every feature of the SDK in one bundle, walked in twenty-one verified stops

examples/grand-tour composes the whole plugin spine in one bundle and walks it in twenty-one stops. Each stop is one prompt, a scripted model response, and a set of checks against the session log, the journal and the requests the runtime actually built. It runs with no API key on a scripted model, and the same stops are its test suite.

Where mini-harness proves the extension points are enough for a coding agent, the tour proves every battery works when mounted together, and shows what each one looks like from the outside: the tool calls, the injected context, the events a UI would render.

How it is built

  • src/harness.ts is the whole composition: one defineBundle of rows, every row an ordinary plugin. dumpConfig prints it; a Patch edits it by id.
  • src/model.ts is the scripted model. Each stop installs a responder that reads the request the runtime built (system prompt, history, tool schemas, the last tool result) and answers like a capable model would. That is documentation as much as test fixture: the responder shows what the model sees at each point.
  • src/stops.ts is the tour: a prompt, a responder, and checks. Stops with no prompt drive the runtime directly (commands, realms, patches).
  • src/journal.ts turns runtime events into a timeline. The CLI prints it and the dashboard streams it over server-sent events; neither hooks into the loop.

Row order matters and is stated in the file: the journal mounts first so it observes every tools/ask before the approver answers, and hooks mounts before approvalPolicy so a hook can veto a call before anyone is asked.

What a stop looks like

The hook itself is one line of config in the bundle: a PreToolUse shell command that reads the call on stdin and exits non-zero to refuse it.

In live mode

--live sends the same prompts to a real provider. The checks then describe what the model did rather than what it had to do; a capable model passes most of them, and a check that fails there is a model choice, not a harness defect.
