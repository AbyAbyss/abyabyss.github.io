Client

A client talks to an agent that runs on a server: it creates or resumes a session, streams the session’s events, and calls every action the server exposes (send, approve, answer, cancel, history, models, workflows, MCP, RAG). There is one in each language, with the same verbs:

PackageRuns inTypical use
@agentkit/client (TypeScript)Browsers and Node, no dependenciesWeb UIs (the React, Vue and Svelte bindings are built on it), Node services
agentkit.client (Python)asyncioBackend-to-backend calls, bots, CLIs, notebooks, tests
client package (Go)goroutinesServices, CLIs, load tests
agentkit::client (Rust, feature client)TokioServices, CLIs, native apps

Every client works against every server: a Go service can drive a Python agent, and a React page can drive a Rust one. See the wire protocol for what goes over the network.

Connect and chat

Section titled “Connect and chat”

connect(url, options) creates a session (or resumes one with sessionId) and returns a client session. Subscribe to events with on, then send a message: send waits for the event stream to be open, posts the message and returns the run’s result once the handlers have seen its done.

The Python, Go and Rust samples start a server in the same program so they run as they are; in your code the URL points at your deployed server.

  • Python

Python takes these as keyword arguments (token=, tenant=, session_id=, reconnect=); Go and Rust take a ConnectOptions struct, which also accepts your own HTTP client (HTTPClient / http_client) and a page URL to resolve a relative agent path against (PageURL / page_url). In a browser the TypeScript client accepts a same-origin path such as connect("/api/agent").

Status, reconnects and errors

Section titled “Status, reconnects and errors”

The event stream opens on the first on, onAny or onStatus and reports its state: connecting, open, reconnecting, closed. When it drops, it re-opens with exponential backoff. A 401 or 403 is final: the status goes to closed with the error, because retrying will not help.

Every call checks the response and raises AgentKitError with status, message and the body on failure. Status 0 means a network failure. A partial stream followed by an error is not a success: show the message.

connect fails at once when the server is down. When a page or service may start before its server, use connectWithRetry(url, { ...options, onRetry, signal }) (Python connect_with_retry, Go client.ConnectWithRetry, Rust client::connect_with_retry). It keeps trying while the server is unreachable or answers 5xx, with the same backoff, and fails at once on any other answer. The React, Vue and Svelte useAgentSession use it.

Approvals and questions

Section titled “Approvals and questions”

When a tool needs approval, the run pauses and the stream carries approval:request with a requestId, the tool name, a preview and the arguments. The run continues once someone calls approve(requestId) or reject(requestId). A question from the agent works the same way with elicitation:request and answer(requestId, choice).

Session API

Section titled “Session API”

The same verbs exist in every client. The names below are TypeScript’s; Python and Rust use snake_case (get_mode, edit_todo, save_workflow), Go uses exported names (GetMode, EditTodo, SaveWorkflow) and takes a context.Context first.

Language notes

  • Python: every network verb is a coroutine (await session.send(...)). Handlers are plain callables run on the event loop; hand async work to a queue or asyncio.create_task. close() is synchronous; await session.aclose() also waits for the stream to end.
  • Go: handlers run on the stream’s reader goroutine, so guard shared state with a mutex and do not block in them; call Approve and friends from another goroutine. Close() returns at once (a handler may call it); Shutdown(ctx) also waits for the goroutine.
  • Rust: handlers are Fn(&Value) run on the task that reads the stream; keep them short and send work over a channel. close() returns at once, shutdown().await waits. Dropping a Session closes its stream, so keep it alive while you listen.
  • TypeScript: in Node without EventSource, the client streams the same SSE body with fetch. Do not import @agentkit/core in the browser: the agent runs on the server.

Several agents

Section titled “Several agents”

Against a server started with serveAgents, connectAgents(url) lists the agents and connects to one. streamAll(url, options) opens one stream for every session of the tenant (GET /events/all), each event carrying its sessionId.

Session hub

Section titled “Session hub”

A UI with many chats wants all of them live: a background chat should keep streaming while the user reads another. createSessionHub(url, options) opens one /events/all stream and folds every event into its session’s state with the reducers below. hub.session(id) returns a client session bound to that id, with every verb.

  • TypeScript
  • Python
  • Go
  • Rust
MemberWhat it does
session(id)A client session for id (the same object per id). Its calls carry id; its on and onAny see that session’s events plus agent-wide ones (MCP, models) from the shared stream
state(id){ conversation, pending, workflow, plan, todos, usage }; an empty state for a session it has not seen
sessions(), subscribe(fn)The ids it knows, in order; fn runs after any change
seed(id), create(), forget(id)Load a session’s history; start a new session; drop one’s state
status, onStatus(fn), close()The shared stream

The hub loads the saved workflows on each (re)connect, so a workflow run shows every step up front.

UI state

Section titled “UI state”

Pure reducers turn the event stream into what a UI renders. Each is (state, event) => state, so they work in any framework and in tests. All four clients ship the session reducers the hub uses:

ReducerState
reduceConversation{ messages: [{ id, role, text, thinking?, tools, artifacts, parts, status, error? }], streaming }. parts interleave text, thinking, tool calls and questions; status is streaming, done, stopped or error. Workflow-step and subagent events are left out unless { includeNested: true }
reducePending{ approvals, questions }, cleared by approval:resolved, elicitation:resolved, the gated tool’s result and the end of the run
reduceWorkflowRun{ runs: [{ runId, workflowId, name, steps, status, output?, error? }], generating?, savePrompt? }
reduceUsage{ tokens, inputTokens, outputTokens, cost, history }, cumulative across plan steps and subagents
reducePlan, reduceTodos{ plan? }, { todos }

Python has them in agentkit.client.state (reduce_conversation, …), Go in package client/state, Rust in agentkit::client::state. TypeScript adds reduceMcp and reduceEventLog (with groupByPhase), plus stores that pair a reducer with its actions and match the Svelte store contract:

The other TypeScript stores are workflowRunStore (run, generate, save, dismissSavePrompt), workflowsStore, mcpStore, usageStore, eventLogStore, todosStore (edit), planStore, and createStore(feed, reducer, initial) for your own reducers. A store takes a client session or any { onAny } event source such as streamAll().
