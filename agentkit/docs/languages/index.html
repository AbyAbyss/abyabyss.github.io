Languages

AgentKit ships the same engine four times. Each SDK runs the whole runtime in your process (providers, tools, memory, MCP, RAG, workflows, approvals, telemetry, the plugin kernel, the workspace tools, the server and the client), so none of them is a thin client for a service written in another language.

TypeScript is the reference. The Python, Go and Rust engines are ports checked against it: all four replay the same conformance fixtures, and every client passes the same contract suite against every server. This page is the map between them. Every other page in these docs shows its samples in all four languages, and the tab you pick is remembered across pages.

Config keys

Section titled “Config keys”

There is one configuration schema. The Configuration reference documents each key once, using the TypeScript spelling; this is how each language writes it.

  • TypeScript and Python take the keys exactly as documented: an object literal in TypeScript, a dict in Python ("toolSearch", "durableSessions", "__test"). Python also accepts snake_case keys ("tool_search"), which TypeScript would reject. Because the keys are the same, a config stored as JSON moves between the two unchanged.
  • Go takes an agentkit.Config struct. Each field is the key with its first letter capitalised (ToolSearch, DurableSessions), and each nested block is its own struct in the package it configures. Optional scalars are pointers where zero means something (CompactAt *float64, Enabled *bool), so a nil pointer means “use the default”. A block that TypeScript switches off with false has a Disabled field (Memory: &memory.MemoryConfig{Disabled: true}) or a No... field (NoThinking: true).
  • Rust takes an agentkit::Config struct with snake_case fields (tool_search, durable_sessions). Every optional field is an Option, so None means “use the default” and Some(0) or Some(false) stay expressible. Config has no Default because the provider is required: start from Config::new(provider) and fill the rest with struct update syntax. TypeScript’s T | false is OrFalse<T> and boolean | T is BoolOr<T>.

The same agent in all four:

Events and payloads

Section titled “Events and payloads”

Event names are identical everywhere (stream:token, tool:call, approval:request, cost:update, done). So are payload keys: anything that is emitted, sent over the wire, recorded or persisted keeps TypeScript’s camelCase keys (requestId, toolName). That is what lets a TypeScript UI read a Python server, and a recording made by one engine replay in another.

How a handler sees a payload depends on the language. Python hands it a dict (typed as a TypedDict in agentkit.types.events). Go and Rust offer typed keys that pair an event name with its payload struct, so the compiler checks both sides; the untyped on("name", fn) form also exists.

  • TypeScript
  • Python
  • Go
  • Rust

Over the wire, the Python client hands handlers dicts, the Go client map[string]any, and the Rust client &serde_json::Value, all with the TypeScript keys.

Where the ports behave differently

Section titled “Where the ports behave differently”

The ports match TypeScript’s observable behaviour, including JavaScript details wherever they reach the wire, a prompt or a fixture: compact JSON.stringify output, JavaScript number formatting, toFixed rounding, and string lengths in UTF-16 units. A few differences come from the host language:

  • Go maps print sorted. Go maps have no insertion order, so a JSON object built from a map[string]any lists its keys sorted. Use a struct or a json.RawMessage where key order matters.
  • Rust results are JSON. result.output, tool results and wire payloads are serde_json::Value; decode them into your types at the edge. serde_json is built with preserve_order, so objects keep TypeScript’s key order.
  • Python takes snake_case keys too, next to the TypeScript keys.
  • Session ownership. TypeScript routes a session’s events with AsyncLocalStorage. Go carries the owning session in the turn’s context, Rust in a Tokio task-local, and Python in a context variable, so the server still sends subagent, RAG and MCP events to the session that raised them.
  • The servers use each language’s HTTP stack: Node’s http in TypeScript, an ASGI app on uvicorn in Python, net/http in Go, axum in Rust. The routes, status codes, JSON bodies and event frames are the same.
