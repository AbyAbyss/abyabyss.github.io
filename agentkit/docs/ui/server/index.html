Serve over HTTP

The agent runs on your server. Browsers, mobile apps and other services reach it over HTTP: they create a session, open an event stream and post messages. Every AgentKit engine ships the same server, with the same routes, status codes, JSON bodies and event frames, so a UI built against one backend works against the other three without a code change. The wire protocol page lists the routes and frames; this page is about running the server.

There are three ways to serve an agent, in every language:

ShapeUse it when
Standalone (serve)The agent is its own service. It listens on a port, optionally serves your built UI from the same origin, and needs nothing else.
Mounted (createAgentHandler)You already have an HTTP app (Express, ASGI, net/http, axum) and want the agent under a path such as /api/agent. Paths the agent does not own fall through to your app.
Several agents (serveAgents)One process hosts a support agent, a research agent and so on, each at /agents/<id>/.

All three apply the same hardening: a 4 MiB body limit, random session ids, a session cap, an auth hook, tenant isolation, Origin and Host checks, and error mapping (a failed run answers 500 with { error }, never a stack trace).

Packages and features

TypeScript: @agentkit/server. Python: the server extra (uv add 'headless-agentkit[server]'), which brings uvicorn. Go: package github.com/AbyAbyss/agentkit/sdks/go/server, plain net/http. Rust: the server Cargo feature, built on axum 0.8.

The default port is 8787 and the default host is 127.0.0.1. Bind 0.0.0.0 (host) to accept connections from other machines, and set allowedHosts when you do (see Origin and Host checks). Closing the server ends every open event stream, so a graceful shutdown does not hang on connected browsers.

Spelling per language

The names above are TypeScript’s. Python takes them as keyword arguments in snake_case (allowed_hosts=, keep_alive_ms=, static=). Go puts the handler options in server.HandlerOptions (AllowedHosts, KeepAliveMs) embedded in server.ServeOptions, which adds Port, Host and Static; ArtifactsDir plus NoArtifacts replace false, and Next is Go’s fall-through handler. Rust nests HandlerOptions under ServeOptions.handler, names the static map static_dirs and spells false as OrFalse::Disabled. See Languages for the general rules.

Mount in your own app

Section titled “Mount in your own app”

Mount the handler when the agent should live inside an app you already run. With basePath set, it answers under that prefix and hands every other request to your app, before auth runs.

  • TypeScript
  • Python
  • Go
  • Rust

Express or Connect take the handler as middleware. It resolves true when it answered and calls next() otherwise.

Runtimes built on the Fetch API (Next.js route handlers, Bun, Deno, Cloudflare-style workers) take toFetchHandler, which returns (request: Request) => Promise<Response>:

The handler is an ASGI app. Pass your own ASGI app (FastAPI, Starlette, Django’s ASGI app) as app and it receives every request the agent does not own; serve the result with any ASGI server (uvicorn module:app, Hypercorn, Granian).

to_asgi_app(agent_or_agents, **options) is the counterpart of TypeScript’s toFetchHandler: one agent or a dict of agents, unknown paths answer 404.

server.CreateAgentHandler returns an http.Handler. Requests it does not own go to Next (or get 404).

create_agent_handler returns an AgentHandler. Its router() is an axum::Router to merge into yours; paths it does not own fall through to your routes and fallback.

The handler is not a bare Router because a Router cannot be closed: call handler.close().await before a graceful shutdown, or the shutdown waits on open SSE connections.

Several agents on one server

Section titled “Several agents on one server”

serveAgents puts each agent at /agents/<id>/ (change it with a basePath containing :id) and answers GET /agents with the ids. Each agent keeps its own sessions, models and MCP servers. createAgentsHandler is the mountable form.

  • TypeScript
  • Python
  • Go
  • Rust

A client reaches one agent with connectAgents(url).agent("support").connect() (see Client). mcpServers takes one list for every agent or, per agent, a map keyed by id (Go: MCPServersByAgent; Rust: mcp_servers_by_agent).

Auth and tenants

Section titled “Auth and tenants”

auth sees the raw request, so it can check a bearer token, a cookie or a signed header. It runs before routing for every API request, SSE stream and WebSocket upgrade; a false answer is a 401 and the client treats 401 and 403 as final (it stops reconnecting).

Tenants come from the x-agentkit-tenant header (rename it with tenantHeader). A session created under one tenant cannot be read, streamed or posted to under another, and GET /events/all streams only the caller’s tenant. Derive the tenant from the authenticated identity in a proxy or in your own middleware rather than trusting a client-chosen value when tenants must not see each other.

The clients send both headers for you: connect(url, { token, tenant }) in TypeScript, token= and tenant= in Python, ConnectOptions{Token, Tenant} in Go and Rust.

Origin and Host checks

Section titled “Origin and Host checks”

Three checks run before routing:

  • Origin. With cors set to a specific origin or { origins }, a request whose Origin is neither allowed nor the server’s own gets 403: every method, SSE streams and WebSocket upgrades. Requests with no Origin (curl, server to server) pass.
  • Host. allowedHosts refuses other Host headers with 403, which stops DNS rebinding. A standalone server bound to a loopback address answers only to localhost, 127.0.0.1 and [::1] with its port unless you set allowedHosts; other binds have no Host check unless you set it.
  • JSON bodies. POST, PUT and PATCH need Content-Type: application/json, else 415, so a cross-site HTML form cannot post to the agent. Every AgentKit client sends it.

WebSocket transport

Section titled “WebSocket transport”

transport: "websocket" turns GET /events?sessionId=<id> into a WebSocket that carries the same { type, payload, timestamp } frames as SSE. The REST routes do not change. Use it behind infrastructure that buffers or times out SSE; SSE is simpler everywhere else, works through most proxies and reconnects on its own. Python serves it through the ASGI websocket scope, Go through its own upgrade, Rust through axum’s WebSocket support; with Express, hand upgrade events to handler.upgrade as shown above.

Sessions on the server

Section titled “Sessions on the server”

A wire session is created by POST /session and wraps one agent session (history, mode, pending approvals). Ids are random; pass an existing sessionId to resume. The server keeps up to maxSessions (default 1000) and evicts the oldest beyond that; a stream or post to an evicted session gets 404, and the client creates a new one. Sessions live in memory unless the agent has durable sessions configured (see Memory), in which case their history survives a restart.

GET /events/all streams every session of the tenant over one connection, with sessionId on each event. That is what the session hub in each client uses to keep many chats live at once.

Model routes in a custom server

Section titled “Model routes in a custom server”

If you write your own HTTP layer instead of using the handler, you can still reuse the model routes (GET /models, POST /models/default, /models/test, /models/add, /models/remove, /models/refresh, GET /models/usage): handleModelRoutes(agent, req, res, pathname) in TypeScript, handle_model_routes in Python, server.HandleModelRoutes in Go and server::handle_model_routes in Rust. Each answers the request and returns true when the path was a model route. See Models and switching.

Production notes

Section titled “Production notes”
  • Proxies. Turn off response buffering for /events (for nginx, proxy_buffering off), and keep the proxy’s idle timeout above keepAliveMs.
  • Slow clients. Every stream has its own queue, so a slow browser never stalls the agent. A session route waits briefly for its streams to write what its call produced, so /send never answers before its tokens have gone out.
  • Shutdown. Close the server or handler first (it ends the streams), then the agent (it closes MCP connections and stores).
  • Body size. Requests over 4 MiB get 413. Send large documents through RAG ingestion in chunks.
  • Health. GET /health answers { ok: true, ... } plus your health() fields; GET /capabilities describes the agent (modes, workflows, MCP, RAG, models) and is what UIs read to decide which controls to show.
  • Static UI. Serving the UI from the same origin (static) avoids CORS entirely.
