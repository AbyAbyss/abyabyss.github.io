What is in it

What works, and what is still a shell

InkTerm is early. Some parts do real work today, others are finished-looking screens waiting for a backend. Each card says which.

Terminal

Works today

The main panel, and the part that actually runs things.

  • Multi-tab sessionsOpen, switch and close tabs.
  • File browser overlayFolder thumbnails and a file preview, read from your disk.
  • Status barConnection, branch, encoding, split and stats toggles.
  • Optional right-side statsCPU, memory, network, processes, threads, uptime.
  • Runs your commandsOne at a time through the platform shell (sh -c, or cmd /C on Windows). A real PTY is not there yet.

AI agent and MCP

UI shell

The screens exist. The backends are the next job.

  • AI agent panelModel selector, chat, trace view and saved prompts. Replies are not wired to a provider yet.
  • MCP managerServer list, per-server tool toggles and an environment variable editor. It does not start or stop real servers yet.

Themes, settings, window

Works today

The personality of the app.

  • Five themesCartoon, Manga, Glass, Dark Pro and Retro. Alt+T cycles them.
  • SettingsTheme picker, font size, animations, status bar and stats panel toggles.
  • Keyboard jumpsAlt+1 to Alt+4 for Terminal, AI, MCP, Settings.
  • Frameless, transparent windowBuilt on Tauri 2 for macOS, Linux and Windows.

How it works

A web UI in a Rust shell

The interface is React 19 and TypeScript, bundled by Vite, with Zustand for state. Tauri 2 hosts it in a native window and gives it a handful of Rust commands.

UI (src/)

React 19, TypeScript 5, Zustand. Panels, themes and the store.

→

Tauri 2 commands

The UI calls invoke(). Rust answers (src-tauri/).

→

Your machine

The platform shell, the filesystem, and CPU, memory and network counters via the sysinfo crate.

Rust commands exposed

  • get_system_stats CPU, memory, network
  • execute_command run a command in a directory
  • list_directory, read_file for the file browser
  • read_mcp_config, write_mcp_config in the config dir
  • get_home_dir start location

Opened in a plain browser instead of the Tauri window, the stats fall back to random sample data.

Not done yet

  • Real shell integration (PTY) instead of mock session output
  • Wire the AI agent to configured providers
  • Start, stop and configure real MCP servers
  • CI, releases and signed installers
  • Documentation and a contribution guide

This is the project's own roadmap. APIs, UI and packaging will change.

Download

No installers yet. You build it.

Status: no releases

There are no prebuilt installers to download. The Releases page is empty, and signed installers are on the roadmap.

To try InkTerm, build it from source. It takes a Node.js and Rust toolchain and a few minutes of compiling.

Version in the repo: 0.1.0.

First launch

macOS will say it can't verify InkTerm (free side project, not notarized).

An app you build on your own machine opens normally. This applies to builds you copy to another computer.

macOS Gatekeeper

Open System Settings → Privacy & Security and click Open Anyway, or run this in Terminal:

xattr -dr com.apple.quarantine /Applications/InkTerm.app

Windows SmartScreen

Windows shows a SmartScreen prompt. Choose More info → Run anyway.

Linux AppImage or .deb

Tauri writes an .AppImage and a .deb under the bundle folder. There is no prompt, but an AppImage needs the executable bit:

chmod +x InkTerm_*.AppImage && ./InkTerm_*.AppImage

Build from source

Four commands

  • Node.js 18+
  • Rust stable
  • Tauri platform dependencies
01

Clone

Get the source.

$ git clone https://github.com/AbyAbyss/InkTerm.git
$ cd InkTerm
02

Install

Pull the JavaScript dependencies.

$ npm install
03

Run

Starts Vite and opens the desktop window. The first Rust compile is slow.

$ npm run tauri dev
04

Build

Makes the app bundle for the OS you are on.

$ npm run tauri build

Artifacts land in src-tauri/target/release/bundle/. Tauri builds for the OS it runs on, so build on each system you want.
