Workflows

Static workflows

Declarative DAGs with tool, AI, and branch steps

Static workflows are named, ordered step lists you define at agent startup. Each step runs on the shared workflow engine: tools call your Zod execute handlers, AI steps run a short runReasoningLoop (mode: "direct", maxSteps: 3), and branch steps evaluate a condition then run nested steps.

Use static workflows for repeatable pipelines (ETL, weekly reports, gated tool chains) where the graph is known ahead of time. For graphs produced from natural language at session time, see Dynamic workflows (experimental).

Enable workflows

Pass workflows: {} (or { definitions: [...] }) so the agent creates an in-memory store. Without this key, agent.workflow() and agent.workflows are unavailable.

agent.capabilities().workflows is true when the store exists.

Builder API

Chain .step() calls, optional .branch(), then .build(). The builder saves the definition to the store on build() (and when using .workflow() on the agent).

Step kindBuilder shapeRuntime behavior
Tool{ tool: "name", input?: object | string }executeToolWithRetry with interpolated args
AI{ ai: "prompt", input?: string }Reasoning loop; input appended as context
Fn{ fn: "label", input?: object | string }Placeholder only — stores { fn, input } in results; no host callback
Branch.branch(condition, (b) => b.step(...).build())If condition is truthy, run nested steps

Full runnable sample: examples/workflow-demo/src/index.ts (pnpm example:workflow with AGENTKIT_DEMO=mock).

Branch conditions are interpolated the same way, then evaluated (literal true/false, or a small results expression).

Steps run in array order; depends on WorkflowStepDef is stored for saved dynamic graphs but not used by the static runner to reorder execution.

Preloaded definitions

Store API

MethodDescription
agent.workflows.list()All definitions
agent.workflows.get(id)One definition
agent.workflows.run(id)Execute; returns { results: Record<string, unknown> }
agent.workflows.delete(id)Remove from memory store

Events

Subscribe on the agent bus (or wire SSE — same event names):

EventWhen
workflow:step:start{ workflowId, stepId } before a step
workflow:step:doneAfter step completes (including branch shell)
logworkflow run: <id> at start

Static runs do not emit workflow:generated (dynamic only).

Approvals and orchestration

Workflow tool steps use the same normalized tools and approval config as agent.run(). AI steps use the orchestrator loop with your provider and optional approvals / context.compactAt.

Parallel subagents (orchestration.parallel) apply to agent.run() / normal session.send, not to workflows.run().
