    OutsideRoot: "deny" | "ask" | "allow"

    What happens to a file path that resolves, after symlinks, outside the root and outside every extra root.

    • "deny" (the default): refuse it, with a reason that names this setting.
    • "ask": ask through tools/ask, the runtime's approval seam. With no responder installed nothing can answer, so it is refused, and a headless agent never hangs.
    • "allow": permit it. There is then no file containment at all: symlinks, .. and absolute paths all reach outside the root.

    This governs the file seam only. A shell command run through the subprocess provider is not confined by it; real isolation needs an OS sandbox.
