Logging and telemetry

AgentKit reports what an agent does at three levels of detail:

LayerWhat you getTurn it on with
EventsEvery step as a typed event: tokens, tool calls, approvals, costs. Always onagent.on(...), onProgress, the wire stream
LoggingLog lines at a level you choose, to stdout or your own loggerlogging
TelemetryTraces: one root span per turn with child spans for model calls, tools, approvals, MCP, memory and more, exported to a collectortelemetry

All three work the same in every language, and the event and span shapes are identical, so a Python agent and a Go agent show up the same way in one dashboard.

Tokens and cost

Section titled “Tokens and cost”

cost:update fires after each model call with the running totals for the turn: tokens (input, output, total), cost in USD (input, output, total) and the provider. Prices come from the provider’s table (see Pricing and cost); agent.models.usage() aggregates per model across turns, and result.usage has the totals for a finished run.

Watch a run in the terminal

Section titled “Watch a run in the terminal”

attachConsole prints a compact live trace of a session or agent to the terminal (model calls, tool calls with arguments and timings, approvals, costs) and returns a function that detaches it. It is the quickest way to see what an agent is doing while you develop.

Telemetry

Section titled “Telemetry”

Add a telemetry block and the agent exports traces built for agents, not generic HTTP spans: a turn root span per message, with child spans for each model call (llm), tool call (tool), subagent, approval, MCP call, memory and RAG access, context compaction, workflow and plan step. Spans carry tokens, cost, model, tool names and errors. Remove the block and nothing is sent.

Spans go to a collector at endpoint (else the AGENTKIT_TELEMETRY_URL environment variable). With neither, they go only to your onSpans callback, or to stdout with sink: "stdout". result.traceId links a turn to its trace.

Privacy by default

Telemetry exports structure (names, timings, tokens, costs, errors), not content. Prompts, completions, tool argument values and memory contents stay out unless you turn them on, and redact masks named fields even then.

OpenTelemetry and tracing in Rust

Section titled “OpenTelemetry and tracing in Rust”

Rust has one more sink: with the tracing Cargo feature, TracingSink turns every AgentKit span into a tracing span with its name, parent and attributes. A program already on tracing-subscriber or an OpenTelemetry exporter then sees agent turns, model calls and tool calls in its own traces. TypeScript, Python and Go have no counterpart; in those, export to the collector or tap onSpans and forward to your OpenTelemetry SDK.

Over the wire

Section titled “Over the wire”

Every event, log and cost:update included, streams to clients over the server’s event stream, so a browser UI can show an activity feed or a cost meter (the React CostMeter and DevLog components do). There is no separate logging API. See Streaming.

EventPayload
loglevel, message, data
cost:updatetokens, cost, provider, traceId
tool:call, tool:result, tool:errorTool activity
error, doneHow the turn ended
