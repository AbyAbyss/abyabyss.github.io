Client

@agentkit/client over AG-UI

Framework-agnostic browser/Node connector. Handles session creation, the SSE event stream (with auto-reconnect), every REST action the server exposes, and pure reducers that turn events into UI state. It has no dependencies and no Node-only code. When the server uses transport: "websocket", connect with a WebSocket client to /events?sessionId=... instead.

The stream opens on the first on / onAny / onStatus and re-opens with exponential backoff when it drops. 401 / 403 are final: the status goes to closed with the error.

connect() itself fails at once when the server is down. When a page may load before its server, use connectWithRetry(url, { ...options, onRetry?, signal? }): it keeps trying while the server is unreachable (status 0) or answers 5xx, with the same backoff (reconnect; false disables), calls onRetry(error, attempt) before each new attempt, stops when signal aborts, and fails at once on any other answer (401, 404…). The React, Vue and Svelte useAgentSession use it.

In the browser the base URL may be a same-origin path (connect("/api/agent"), e.g. a Next.js route using toFetchHandler); it resolves against the page.

Several agents, several sessions

Session hub

createSessionHub(url, options?) does that routing for you: one /events/all stream, every event folded into its session's state with the reducers below, so sessions in the background keep updating while the UI shows another.

Member
session(id)A ClientSession for id (the same object per id): every call carries id, on / onAny see that session's events plus agent-wide ones (MCP, models) from the shared stream, send / answer emit client:send / client:answer, workflows.run closes the run in the hub's state when it returns. Pass it to any store or hook. Its close() detaches its listeners only
state(id){ conversation, pending, workflow, plan, todos, usage }; emptySessionState for a session it hasn't seen
sessions() / subscribe(fn)Ids it knows (from events, session(), seed(), create()), in order; fn runs after any change
seed(id) / create() / forget(id)Load history; start a session; drop one's state
status / onStatus(fn) / close()The shared stream

options are connect()'s (token, tenant, reconnect) plus conversation (passed to reduceConversation, e.g. { includeNested: true }). The hub loads the saved workflows (GET /workflows) on each (re)connect so a run shows every step up front.

UI state

Pure reducers turn the event stream into the state a UI renders. They are (state, event) => state, so they work in any framework, in tests and in a plain <script type="module">.

ReducerState
reduceConversation{ messages: [{ id, role, text, thinking?, tools, artifacts, parts, status, error? }], streaming } (status: streaming / done / stopped / error; stopped when the run was stopped, from done with status: "stopped") — parts interleave text, thinking, tool calls and questions (with the user's answer, from the local client:answer event); workflow-step and subagent events (scope) are left out unless { includeNested: true }
reducePending{ approvals, questions } — cleared by approval:resolved / elicitation:resolved, the gated tool's result, and run end
reduceWorkflowRun{ runs: [{ runId, workflowId, name, graph?, steps: [{ id, kind, label, tool?, input?, prompt?, status, output? }], status, output?, error? }], generating?, savePrompt? }
reduceUsage{ tokens, inputTokens, outputTokens, cost, history } — cumulative across plan steps and subagents
reduceMcp{ servers, tools }
reduceEventLog{ rows: [{ id, at, phase, type, summary, payload, count? }] } — tokens merged, human summaries; groupByPhase(rows)
reduceTodos / reducePlan{ todos } / { plan? }

Session stores pair a reducer with its actions and keep it in sync while subscribed. Their subscribe matches the Svelte store contract.

A store takes a ClientSession (from connect() or hub.session(id)) or a bare event source ({ onAny }, e.g. streamAll()): without a session the state follows the events and the actions reject with "Session not connected".

Also available: workflowRunStore (run, generate, save, dismissSavePrompt), workflowsStore (refresh, load, remove, save), mcpStore (server actions), usageStore, eventLogStore, todosStore (edit), planStore, and createStore(feed, reducer, initial) for your own reducers.
