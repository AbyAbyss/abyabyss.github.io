React

Any backend

@agentkit/react runs in the browser and talks to an AgentKit server over the wire protocol. The server can be written in TypeScript, Python, Go or Rust: the hooks and components below work unchanged against all four, so you can move the backend to another language without touching this code. See Serve over HTTP for the server side in each language.

Hook: useAgentSession

Section titled “Hook: useAgentSession”

Connects on mount (same wire as @agentkit/client). Returns ready, client (the live session, as state), session (a ref to it), status (connecting / open / reconnecting / closed), error, on, send(input, options?), approve, reject, answer, cancel, saveWorkflow, and the last 200 events.

It reconnects only when the URL or the token / tenant / sessionId values change, so passing an inline options object is fine. When the server is down as the page loads, it keeps trying with the stream’s backoff (reconnect), with status "reconnecting" and error set meanwhile (connectWithRetry from @agentkit/client); 4xx answers fail at once.

Register on() handlers only after ready === true. Unsubscribe in the useEffect cleanup.

State hooks

Section titled “State hooks”

Most UIs don’t need on() at all: pass client to a state hook and render what it returns. Each hook wraps a pure reducer from @agentkit/client, so the same logic runs in Vue, Svelte and plain JS.

HookReturns
useConversation(client, { includeNested? }){ messages, streaming }; each message has text, thinking?, tools, artifacts, ordered parts, status; workflow-step and subagent events stay out unless includeNested
usePendingRequests(client){ approvals, questions, approve, reject, answer }; a request disappears when it is settled anywhere (here, another tab, an admin console) or the run ends
useWorkflowRun(client){ runs, generating, savePrompt, list, run(id, input?), generate(task), refreshList }
useWorkflows(client){ workflows, refresh, get, remove, save }
useMcp(client){ servers, tools, refresh, connect, disconnect, reload, add, remove, completeAuth }
useUsage(client, { maxHistory? }){ tokens, inputTokens, outputTokens, cost, history }, cumulative
useEventLog(client, { mergeTokens?, max?, exclude? })audit rows { id, at, phase, type, summary, payload }; group with groupByPhase from @agentkit/client
useTodos(client){ todos, edit(id, patch) }
usePlan(client)the current plan with step statuses, or undefined

All hooks accept null while connecting and return empty state; a new session starts fresh. They take a ClientSession, a hub’s hub.session(id), or a bare event source ({ onAny }, e.g. streamAll(); actions then reject).

Many sessions: useSessionHub

Section titled “Many sessions: useSessionHub”

For a UI with many chats that keep streaming in the background (a sidebar of conversations), hold one hub instead of one session per chat. useSessionHub(url, opts?) creates a createSessionHub (one /events/all stream, every session folded into its own state) on mount and closes it on unmount; it returns null until then and is recreated only when the URL, token or tenant change.

HookReturns
useSessionHub(url, opts?)SessionHub | null: session(id), state(id), sessions(), subscribe, seed(id), create(), forget(id), status, onStatus, close (see Client)
useSessionState(hub, sessionId){ conversation, pending, workflow, plan, todos, usage } for that session, re-rendering when it changes; emptySessionState without a hub or id
useHubSessions(hub)the ids the hub knows

Hook: useModels

Section titled “Hook: useModels”

Lists and switches models over the wire, with no custom fetch glue. Opens a lightweight connect() session, subscribes to models:changed, and exposes the same verbs as session.models.

Returns { ready, models, activeId, userConfigurable, setDefault, test, refresh }. Pass optional { token, tenant } as the second argument (same as useAgentSession).

See Models & switching for server setup and wire route table.

Components

Section titled “Components”

Pre-built UI wired to the same events:

  • Chat: streaming tokens
  • Timeline: ordered plan/workflow/tool steps (pass events from your session reducer)
  • TodoPanel: todo:update
  • ToolList: mcp:tools:loaded
  • ApprovalGate: approval:request
  • ChoiceCards: elicitation:request
  • ModelPicker: registry list + onSetDefault (pair with useModels)
  • CostMeter: token and cost display from cost:update
  • DevLog: structured log event feed for debug panels

End-to-end demo: examples/nextjs-chat (pnpm example:nextjs with pnpm example:express in another terminal). Model switching demo: examples/ollama-local (pnpm example:ollama:live).
