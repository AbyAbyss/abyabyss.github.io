Recipes

Every recipe here is a runnable project in the repository, and each common shape exists in all four languages. The Python, Go and Rust versions are ports of the TypeScript ones: they print what their TypeScript twin prints, and their tests run every one of them in mock mode.

No API key needed

Each example runs on a scripted model when AGENTKIT_DEMO=mock is set (the TypeScript scripts ending in :mock set it for you). Drop it and put a provider key such as ANTHROPIC_API_KEY in .env or the environment for a live run.

Run the TypeScript commands from the repository root after pnpm install && pnpm build, the Python ones from sdks/python (after uv sync), the Go ones from sdks/go and the Rust ones from sdks/rust.

A: a task in, a typed result out

Section titled “A: a task in, a typed result out”

A job, an endpoint or a pipeline step: one call, a validated structured answer.

  • TypeScript
  • Python
  • Go
  • Rust

The full examples also give the agent file, shell and HTTP tools and print progress (tool calls, streamed text, cost) to the terminal.

B: the agent behind your server

Section titled “B: the agent behind your server”

The agent’s routes mounted in a web server, with a plain HTML page that chats with it, approves tool calls and shows the stream.

  • TypeScript
  • Python
  • Go
  • Rust

Point the Next.js UI at any other agent server, in any language: NEXT_PUBLIC_AGENT_URL=http://host:8787/api/agent pnpm example:nextjs.

C: a terminal agent with record and replay

Section titled “C: a terminal agent with record and replay”

Run a task with live progress in the terminal, record the session, then replay the recording on another model. Recordings use one format, so a session recorded by one engine replays in any other.

  • TypeScript
  • Python
  • Go
  • Rust

See Record and replay and the replay CLI.

D: a coding agent

Section titled “D: a coding agent”

A terminal coding agent on the workspace preset: sandboxed file and shell tools, approvals before risky calls, and a REPL.

  • TypeScript
  • Python
  • Go
  • Rust

See Coding agent and Building a coding agent.

E: local models, switchable over HTTP

Section titled “E: local models, switchable over HTTP”

Discovers the models in a local Ollama, builds a model registry from them and serves the standard /models routes, so a UI can list and switch models. It falls back to the scripted model when Ollama is not running.

  • TypeScript
  • Python
  • Go
  • Rust

Try it: GET http://127.0.0.1:8796/models, then POST /models/default with { "modelId": "..." } and POST /models/refresh. See Models and switching.

A support bot over a REST API

Section titled “A support bot over a REST API”

A support bot for a company that already has a REST API. It shows the escape hatches together: the API as tools, a prompt that depends on who is talking, hooks, a per-session approval policy, imported history and handoff to a human.

  • TypeScript
  • Python
  • Go
  • Rust

The same browser page on every backend

Section titled “The same browser page on every backend”

examples/vanilla-js-ui/public/index.html is a plain HTML page on the TypeScript @agentkit/client browser bundle. Each engine serves that file unchanged; only the backend differs. It is the clearest demonstration that a UI written once works against a server in any language. Run pnpm build at the repository root once first: every backend serves the client’s browser bundle from packages/client.

  • TypeScript
  • Python
  • Go
  • Rust

A harness built from plugins

Section titled “A harness built from plugins”

A small coding harness assembled from kernel plugins instead of createAgent: local execution, a sandbox, git, session stores and a REPL. Read it to see how the pieces fit. See Mini harness.

  • TypeScript
  • Python
  • Go
  • Rust

Each uses the mock provider when no key is set.

The grand tour

Section titled “The grand tour”

Twenty-two stops that exercise every feature on a scripted model, with a terminal report or a live dashboard on port 8791. The dashboard page is the same file for every backend.

  • TypeScript
  • Python
  • Go
  • Rust

See Grand tour.

TypeScript apps that work with any backend

Section titled “TypeScript apps that work with any backend”

These are full apps in TypeScript. Their UIs talk to the agent over the wire, so the agent server behind them can be swapped for a Python, Go or Rust one.
