Providers

Model registry, routing, Ollama, and hot-swap APIs

provider is the only required field on createAgent. It selects which LLM backs agent.run() and sessions, and optionally enables per-task routing and end-user model management in the UI.

Use a string shorthand for a single built-in provider, or an object when you need custom default model IDs, API keys, fallbacks, or a registry of additional models.

Built-in shorthands

ValueDefault model (approx.)
"anthropic"claude-sonnet-4-20250514
"openai"gpt-4o-mini
"ollama"first tag from local Ollama, or llama3.2
"gemini"gemini-2.0-flash (Google OpenAI-compatible API)
"mistral"mistral-small-latest
"groq"llama-3.3-70b-versatile
"mock"Deterministic script (tests / AGENTKIT_DEMO=mock)

Hot-swap (resolveActive)

The model registry resolves the active provider and model on every session.send() and agent.run(). Call agent.models.setDefault(modelId) (or the wire/client equivalent) and the next turn uses the new model — no manual provider re-instantiation.

Internally, ModelRegistry.resolveActive() reads the current default entry, applies per-entry API keys, and returns a ResolvedProviderConfig for the agent loop.

Object config: routing and registry

FieldPurpose
defaultInitial model id (provider/model or shorthand)
apiKeyShared key for built-in providers
fallbackReserved for future failover
routingPer-mode model ids (planning, reasoning, default)
userConfigurableWhen true, end users may call agent.models.add()
registry.customPre-registered models available to list() / setDefault()

resolveRoutedModel picks routing.planning in plan mode and routing.reasoning in the main loop (exported from @agentkit/core for custom orchestration).

Local models (Ollama)

The built-in Ollama provider wraps an OpenAI-compatible chat endpoint at http://127.0.0.1:11434/v1 by default. Set OLLAMA_BASE_URL for a remote host.

listOllamaModels(baseURL?) lists model tags from a running Ollama instance. agent.models.refresh() (or POST /models/refresh) calls ModelRegistry.refreshOllama() to add missing entries.

Try it: pnpm example:ollama (mock) · pnpm example:ollama:live (requires Ollama running).

Gemini, Mistral, and Groq

These built-ins use createOpenAICompatibleProvider against each vendor's OpenAI-compatible endpoint:

OpenAI-compatible gateways

For Azure, LiteLLM, vLLM, or any OpenAI-style /chat/completions API:

createOpenAICompatibleProvider({ baseURL, apiKey?, id?, inputCostPerToken?, outputCostPerToken? }) returns a Provider suitable for registerProvider.

Session model API (agent.models)

When userConfigurable: true (or for registry-only operations), wire clients and React hooks can manage models:

Events: models:changed, models:test:result, models:usage:update. Custom provider factories beyond anthropic/openai/ollama/mock require registerProvider (advanced).
