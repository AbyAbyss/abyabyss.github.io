Providers

provider is the only required config key. It picks the model behind every run and session turn, and it can also hold a registry of extra models, per-task routing, and a switch that lets end users add their own models.

Every provider is plain HTTP inside the SDK. No vendor SDK is installed in any of the four languages: TypeScript uses fetch, Python uses httpx, Go uses net/http, and Rust uses one reqwest client (rustls, so no system OpenSSL).

The full provider config

Section titled “The full provider config”

Pass an object instead of an id when you need a specific model, your own key, a registry of models to switch between, or a different model per task.

  • TypeScript
  • Python
  • Go
  • Rust
KeyPurpose
defaultThe model a run starts on: provider/model, or a provider id for its default model
apiKeyKey for the default provider; otherwise read from the provider’s environment variable
fallbackA second model id, kept on the resolved config for your own failover logic
routing.planningModel for plan mode (mode: "plan")
routing.reasoningModel for the main tool loop
routing.defaultModel when no task-specific route applies
userConfigurableWhen true, end users may add models (bring your own key) through agent.models and the server’s /models routes
registry.customExtra models offered by agent.models.list() and selectable with setDefault()

Per-language spelling

Python takes the same camelCase keys as TypeScript, in a dict. Go puts the registry entries straight on ProviderConfig.Custom (no Registry wrapper) and uses Go field names; Rust uses snake_case fields and Option for the optional ones. See Languages for the mapping rules.

resolveRoutedModel (resolve_routed_model in Python and Rust, providers.ResolveRoutedModel in Go) returns the model a routing table picks for a task kind, for when you build your own orchestration.

Switch models at runtime

Section titled “Switch models at runtime”

The model registry resolves the active model on every run and session turn. Change the default and the next turn uses the new model: nothing is rebuilt, and running turns finish on the model they started with.

  • TypeScript
  • Python
  • Go
  • Rust

These calls emit models:changed, models:test:result and models:usage:update, and the same operations are served over HTTP by the server’s /models routes, so a UI model picker works against a backend in any language (see Models & switching).

One run on another model

Section titled “One run on another model”

A single run can use another model, or turn reasoning off, without touching the default. The model is a registry id or a provider/model id; an unknown id fails before the run starts.

Local models with Ollama

Section titled “Local models with Ollama”

Ollama runs models on your own machine: no API key, no per-token cost, and nothing leaves the machine. Install it, pull a model that supports tools, and point the agent at it.

  • TypeScript
  • Python
  • Go
  • Rust

ollama runs on a chat model you have installed and lists every installed one in agent.models, so there is no model name to keep in sync. Pin one with default: "ollama/qwen3:8b", or use { default: "ollama", userConfigurable: true } to give users a picker.

WhatHow
Tools, approvals, MCP, workflowsSame as any provider, on models with tool support (Ollama’s model page lists “tools”)
Reasoning modelsthinking: false turns reasoning off (Qwen 3, Nemotron, gpt-oss) for faster answers
Embeddings for memory and RAGOLLAMA_EMBED_MODEL, else the first installed embedding model (nomic-embed-text, mxbai-embed-large, bge-m3), else a local lexical embedding. Never an OpenAI model
Another machineOLLAMA_BASE_URL=http://gpu-box:11434
Ollama’s cloudOLLAMA_BASE_URL=https://ollama.com and OLLAMA_API_KEY
CostCounted as $0

Context length

Ollama sets each model’s context window when it loads it, and silently drops the start of a prompt that is longer. If long chats lose their beginning, raise it on the server: OLLAMA_CONTEXT_LENGTH=32768 ollama serve.

listOllamaModels lists the installed tags and isOllamaEmbeddingModel tells embedding models apart (list_ollama_models and is_ollama_embedding_model in Python and Rust, providers.ListOllamaModels and providers.IsOllamaEmbeddingModel in Go).

Nemotron on any host

Section titled “Nemotron on any host”

NVIDIA Nemotron runs on several hosts, and each is supported. Pick one in config; nothing else in the agent changes.

nemotron(size, host) returns the provider/model id, so the host is one word in config:

  • TypeScript
  • Python
  • Go
  • Rust

Ids work with or without the provider prefix: on nvidia, "nvidia/nemotron-3-ultra-550b-a55b" and nemotron("ultra", "nvidia") name the same model. The ids live in NEMOTRON_MODELS (providers.NemotronModels in Go).

Reasoning. Nemotron reasons before it answers, which can multiply output tokens: a one-line answer from Nano took 3,703 tokens with reasoning and 117 without. thinking: false in the config, or per run, turns it off on Nebius, NVIDIA and Ollama.

Cost. Each size is priced at its Nebius list price (per million tokens: Ultra $1 in and $3 out, Super $0.30 and $0.90, Nano $0.06 and $0.24). The nvidia provider counts $0, since the hosted catalog runs on free credits and a NIM is your own hardware; register a price (below) to track a paid deployment.

OpenAI-compatible gateways and custom providers

Section titled “OpenAI-compatible gateways and custom providers”

Azure OpenAI, LiteLLM, vLLM, OpenRouter, a company gateway: anything that serves an OpenAI-style /chat/completions endpoint becomes a provider with registerProvider and the OpenAI-compatible factory. The factory receives the API key from the config (or none) and returns a provider; models are then named my-gateway/<model>.

  • TypeScript
  • Python
  • Go
  • Rust

A provider that is not OpenAI-compatible implements the provider interface itself: a streaming chat call, a cost estimate and, optionally, embed. The built-in anthropic provider is a complete example in each SDK (packages/core/src/providers/anthropic.ts, sdks/python/src/agentkit/providers/anthropic.py, sdks/go/providers/anthropic.go, sdks/rust/src/providers/anthropic.rs).

Pricing and cost

Section titled “Pricing and cost”

Every provider estimates the cost of each call from a built-in price table, and the agent reports it in cost:update events, in result.usage, and per model in agent.models.usage(). Register a price for a model the table does not know (a fine-tune, a gateway alias, a paid NIM). Prices are USD per million tokens; cache reads default to a tenth of the input price and cache writes to 1.25 times it.

  • TypeScript
  • Python
  • Go
  • Rust

The model name is matched without its provider/ prefix and date suffix, so one entry covers gpt-4o on every provider that serves it.

Testing without a key

Section titled “Testing without a key”

provider: "mock" plays a fixed script and needs no key or network. Set the script under __test.mockScript (Go: Test: &agent.TestConfig{MockScript: ...}; Rust: test: Some(TestConfig { mock_script: .. })), or run with AGENTKIT_DEMO=mock. Every sample on this site runs that way in CI.

For demos and tests that should react to what the user types, the rule provider answers by reading the conversation. Each rule matches the latest user message (a regex) or a predicate, and replies with text, thinking, tool calls, or a function of the context. A tool-call reply whose tools already returned this turn is skipped, so “call the tool” followed by “answer from its result” plays out as one turn; set repeat on a rule to play it anyway (polling, the same tool with new arguments). fallback answers when nothing matches.

  • TypeScript
  • Python
  • Go
  • Rust

The context a rule sees: the messages, lastUser (context a runtime injects mid-turn does not count as the user), toolResults for this turn, results (the same, decoded: JSON parsed and compacted results unwrapped), the names of the offered tools, system, and the regex match.

Regex dialects

Go rules use RE2 (regexp) and Rust rules the regex crate, so lookarounds and backreferences are not available there. TypeScript’s /i flag is (?i) at the start of the pattern in Go and Rust.
