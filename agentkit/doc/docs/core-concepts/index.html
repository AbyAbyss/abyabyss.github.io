Core concepts

Agent, session, events, and modes

Agent

createAgent(config) returns an object with run, session, on, mcp, models, workflow, and related helpers. Configuration is validated at construction time with Zod.

Models

When provider.registry or userConfigurable is set, agent.models manages a hot-swappable registry. The active model resolves on every send() — see Models & switching.

Session

agent.session() is interactive: send, on, approve, answer, cancel, close, setMode. Use this for chat UIs and long-running work with human gates. agent.setMode() applies to subsequent run() calls on the same agent instance.

Switching mode emits mode:changed on the event bus (and over the wire when using @agentkit/server).

Events

All subsystems publish to one typed event bus. Subscribe with agent.on or session.on. The same events map to AG-UI on the wire via @agentkit/server.

Notable groups: stream:* and thinking:* for model output, tool:* / mcp:tool:* for tool calls, plan:* / todo:* for plan mode, cost:update and log for observability, mode:changed for runtime mode switches.
