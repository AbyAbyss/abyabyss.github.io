Extending AgentKit

Two levels, one runtime — from a one-call agent to your own harness

createAgent is the one-call path: configuration goes in, an agent comes out. It covers the common case, and most projects never need anything else.

Underneath it is a plugin kernel, and the same import gives you that too. That is the difference between an SDK you configure and an SDK you build on — the second one lets you ship a coding agent, a review bot, or a domain harness without waiting for AgentKit to add a config key for it.

Two levels

Both levels run the same services, the same tool pipeline, and the same session log. Level 2 is not a rewrite of level 1 — it is level 1 with the lid off.

Why a kernel

The old extension surface was a config schema, and a config schema can only express features its author already imagined. Denying a tool call, wrapping a dispatch with a deadline, rewriting what the model sees, or pointing the filesystem at a remote sandbox each meant patching the runtime.

Now every part of a turn is a service (something you can replace) or an event (something you can intercept). A plugin can deny a tool call, wrap the dispatch, rewrite the prompt, swap the model adapter, add a durable event type, give one session a different tool set, or replace the loop itself — all through public APIs, none of them requiring a change to AgentKit.

That is also the honesty test: AgentKit's own batteries — skills, retrieval, MCP, recall, budgets, structured output, subagents, session persistence, Code Mode — ship as plugins on this spine. Anything AgentKit does, a third party can do too.

Packages

You can import everything from @agentkit/core, which re-exports the spine. The two packages underneath are published separately for anyone who wants the substrate without the batteries:

packagecontains
@agentkit/kernelcontexts, services, reversible effects, inject, a five-mode event bus, bundles. Nothing agent-specific.
@agentkit/runtimethe agent microkernel on that kernel: session log, tool pipeline, prompt assembly, model seam, replaceable loop.
@agentkit/coreboth of the above, plus the Node-side providers and every battery — nodeExecution, nodeTerminals, fetchWeb, fileSpill, settingsFiles, sessionPersistence, nodeCodeRuntime, hooks.

Edge and worker targets can depend on @agentkit/runtime alone; the Node-only pieces (SQLite persistence, node:vm Code Mode, real fs/subprocess) live in @agentkit/core.
